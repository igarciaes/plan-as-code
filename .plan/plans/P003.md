# P003 — Enforce Status Transition Ownership for Tasks and Plans

**Status:** Completed
**Scope:** `SPEC.md`, `SKILL.md`, `examples/`, `CHANGELOG.md`
**Planner:** planner-agent
**Created:** 2026-09-14
**PaC version:** v0.4.0

## Objective

Make explicit in the normative specification and the agent skill that the Implementer advances the Task status (`In Progress`, `Implemented`) and that the Planner advances the Plan status (`Planned`, `Completed`), so that agents stop leaving statuses stale, and keep derived artifacts consistent.

## Scope

### Included

- `SPEC.md` — §8 Plan lifecycle and §9 Task lifecycle status-transition ownership.
- `SKILL.md` — Planner and Implementer procedures.
- `examples/` — Plan and Task statuses consistent with the explicit transitions.
- `CHANGELOG.md` — release entry.

### Excluded

- Validator or schema changes; no new protocol invariants.
- Version bump; PaC remains v0.4.0.
- Migration of the legacy P001/P002 records.

## Constraints

- Status-transition ownership MUST be normative (MUST/SHOULD per RFC 2119) in `SPEC.md` §8 and §9.
- The Implementer MUST NOT mark a Task `Verified`; only the Planner MAY (SPEC §9.6).
- A Plan MUST NOT be marked `Completed` while any required Task is not `Verified` (SPEC §8.3).
- `SKILL.md` MUST stay aligned with `SPEC.md` and conformant with the Agent Skills spec.
- Examples MUST NOT contradict `SPEC.md` or `SKILL.md`.
- Stable IDs are preserved.
