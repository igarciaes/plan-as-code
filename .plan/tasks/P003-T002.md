# P003-T002 — Make Task status transitions explicit in SPEC.md §9

**Status:** Planned
**Owner:** Implementer
**Plan:** P003

## Objective

Add normative statements to `SPEC.md` §9 stating that the Implementer owns the Task's implementation lifecycle state and MUST mark the Task `In Progress` when beginning implementation and `Implemented` when the implementation and its evidence are complete, while preserving the §9.5 reason rule and the §9.6 Planner-only `Verified` rule.

**Depends on:**

- P003-T001

## Definition of Done

- [ ] §9 states that the Implementer owns the Task's implementation lifecycle state (`In Progress`, `Implemented`).
- [ ] §9.3 states the Implementer MUST mark the Task `In Progress` when beginning implementation.
- [ ] §9.4 states the Implementer MUST mark the Task `Implemented` when the implementation and its evidence are complete.
- [ ] §9.5 requires the reason for a failed verification to be recorded; preserved.
- [ ] §9.6 "Only the Planner MAY transition a Task to `Verified`" is preserved.
- [ ] §11 and §13.2 "Task implementation lifecycle state" ownership is consistent with the new language.
