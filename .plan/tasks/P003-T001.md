# P003-T001 — Make Plan status transitions explicit in SPEC.md §8

**Status:** Planned
**Owner:** Implementer
**Plan:** P003

## Objective

Add normative statements to `SPEC.md` §8 stating that the Planner owns the Plan status and MUST mark the Plan `Planned` when it is ready for implementation and `Completed` when all required Tasks are `Verified`, while preserving the existing §8.3 `Completed` constraint and §8.4 `Cancelled`.

**Depends on:**

- None

## Definition of Done

- [ ] §8 states that the Planner owns the Plan status.
- [ ] §8.2 states the Planner MUST mark the Plan `Planned` when it is ready for implementation.
- [ ] §8.3 states the Planner MUST mark the Plan `Completed` when all required Tasks are `Verified`.
- [ ] The existing §8.3 rule that a Plan MUST NOT be marked `Completed` while any required Task is not `Verified` is preserved.
- [ ] The language is normative (MUST/SHOULD per RFC 2119).
