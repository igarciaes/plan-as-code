# F003 — §9.10 Draft→Blocked/Deferred transitions conflict with INV-014

Status: closed

Severity: medium

Location:
SPEC.md §9.10 (lines 457–458)
SPEC.md §17, INV-014 (line 670)

## Observation

The Task transition table permits `Blocked` and `Deferred` from "any (non-terminal)"
state, which includes `Draft` (only `Verified` and `Cancelled` are terminal per §9.6
and §9.9). Meanwhile INV-014 states that a Task in `Blocked` or `Deferred` "requires
its parent Plan to be `Planned` or `Completed`" and MUST NOT be in those states while
the parent Plan is `Draft`.

Because Tasks are defined while their parent Plan is in `Draft` (§9), a `Draft` Task
under a `Draft` Plan could legally transition to `Blocked`/`Deferred` per the table,
yet that resulting state always violates INV-014. The two normative statements are
mutually inconsistent.

## Recommendation

Restrict the `Blocked` and `Deferred` source states in §9.10 (for example
`Planned | In Progress | Implemented` → `Blocked`/`Deferred`) so the table cannot
produce a state INV-014 rejects, or amend INV-014 to allow `Draft` Tasks to be
`Blocked`/`Deferred` under a `Draft` parent Plan.

## Decision

Status: accepted

Rationale:
Restrict `Blocked`/`Deferred` source states to `Planned | In Progress | Implemented` so the table cannot violate INV-014.
