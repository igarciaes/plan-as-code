# F011 — Schemas do not require the normative mandatory fields

Status: closed

Severity: low

Location:
schemas/plan.schema.json (required, lines 7–12)
schemas/task.schema.json (required, lines 7–14)
SPEC.md §6 (lines 175–185)
SPEC.md §7 (lines 241–249)

## Observation

SPEC §6 states a Plan MUST have a stable ID, title, status, scope, Planner identity,
creation metadata, objective, constraints, and task list. SPEC §7 states a Task MUST
have a stable ID, title, status, owner role, parent Plan reference, objective, and
Definition of Done.

The derived schemas require far fewer fields: `plan.schema.json` requires only
`id`, `title`, `status`, `tasks`; `task.schema.json` requires only `id`, `title`,
`status`, `owner`, `plan_id`, `definition_of_done`. Fields the spec marks MUST
(Plan `scope`, `planner`, `created`, `objective`, `constraints`; Task `objective`) are
optional in the projection.

## Recommendation

Align each schema's `required` array with the MUST fields in SPEC §6 and §7, or
document in §20.1 why certain normative fields are not projected.

## Decision

Status: accepted

Rationale:
Align schema `required` arrays with §6/§7 MUST fields; update tests/test_schemas.py:31 and fixtures missing `## Constraints`.
