# F014 — Plan Cancelled transition vs INV-014 leaves Task state unspecified

Status: closed

Severity: low

Location:
SPEC.md §8.5 (line 360, `any → Cancelled`)
SPEC.md §17, INV-014 (line 670)

## Observation

§8.5 permits the Plan to transition to `Cancelled` from any state. INV-014 requires a
Task in `Planned`, `In Progress`, `Implemented`, `Changes Requested`, `Blocked`,
`Deferred`, or `Verified` to have a parent Plan that is `Planned` or `Completed`. A
Plan `Cancelled` while it still has Tasks in those states therefore violates INV-014.

The spec does not state that cancelling a Plan requires first cancelling its Tasks,
nor what Task states are valid under a `Cancelled` Plan. The interaction is
under-specified and can produce an unavoidable invariant violation.

## Recommendation

State explicitly that when a Plan is `Cancelled`, its Tasks MUST be transitioned to
`Cancelled` (or otherwise brought to a state allowed under a `Cancelled` Plan), and
note the corresponding Task states valid under a `Cancelled` Plan.

## Decision

Status: accepted

Rationale:
State that cancelling a Plan requires cancelling its Tasks.

## Verification

- `SPEC.md:667` (INV-014) ends "When a Plan is `Cancelled`, its Tasks MUST be `Cancelled` (see §8.4)."
