# F007 — "accepted Tasks" is an undefined term

Status: closed

Severity: low

Location:
SPEC.md §18.3 (line 699)
SKILL.md (line 42)

## Observation

§18.3 states "The Implementer reads the complete canonical Plan and implements
accepted Tasks". The term "accepted" is not defined in §4 Terminology, and the v0.5.0
workflow (§18) defines no accept operation (Draft, Approve, Implement, Verify,
Complete) and removes acceptance criteria (§15, §22.4). `SKILL.md:42` repeats
"accepted Tasks". The term is a leftover with no defined meaning.

## Recommendation

Replace "accepted Tasks" with "the Plan's Tasks" or define the term. Keep `SKILL.md`
consistent with the chosen wording.

## Decision

Status: accepted

Rationale:
Replace "accepted Tasks" with "the Plan's Tasks" in SPEC.md §18.3 and SKILL.md:42.

## Verification

Status: verified

Evidence:
- `SPEC.md:696` (§18.3) reads "implements the Plan's Tasks"; `SPEC.md:378` similarly.
- `SKILL.md:42` reads "implements the Plan's Tasks and records evidence."
- `README.md:49` reads "implements the Plan's Tasks".

Checks performed:
- `grep -rn "accepted Tasks" SPEC.md SKILL.md README.md` → no matches (exit code 1).
- `grep -n "the Plan's Tasks" SPEC.md SKILL.md README.md` → confirms replacement wording.

## Implementation

Status: implemented

Changes:
