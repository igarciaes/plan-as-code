# F005 — Plan-level Definition of Done is defined but never enforced

Status: closed

Severity: medium

Location:
SPEC.md §6 (line 187; template lines 225–231)
SPEC.md §8.3 (lines 335–343)
SPEC.md §17, INV-012 (line 665)
schemas/plan.schema.json (definition_of_done, lines 73–90)
tools/validate.py (INV-012, lines 346–360)

## Observation

A Plan MAY have a Plan Definition of Done (§6), the canonical Plan template renders
it as "The Plan is ready to be marked `Completed` when:" with checkboxes, and
`plan.schema.json` projects it to `definition_of_done`. However, the Plan completion
rule (§8.3) and INV-012 condition `Completed` only on required Tasks being `Verified`,
and `tools/validate.py` never checks the Plan's own DoD checkboxes. The Plan DoD has
no effect on any normative rule, so a Plan with unchecked DoD conditions can be
marked `Completed` if all Tasks are `Verified`.

## Recommendation

Decide the intended semantics and make them explicit: either (a) include the Plan DoD
conditions in the `Completed` rule (§8.3 and INV-012) and enforce them in
`tools/validate.py`, or (b) remove the Plan-level Definition of Done from the §6
template, §20.1 projection, and `plan.schema.json` so the spec is internally
consistent.

## Decision

Status: accepted

Rationale:
Remove Plan-level DoD: strip from §6 template, §20.1 projection, and `plan.schema.json`; completion stays Task-based.
