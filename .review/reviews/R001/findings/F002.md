# F002 — Invalid relationship combinations not machine-checked

Status: closed

Severity: low

Location:
SPEC.md (§23.2)
tools/validate.py

## Observation

SPEC.md §23.2 normatively requires relationships to be validated for "invalid relationship combinations" (for example a task both `depends-on` and `conflicts-with` the same target) and states that detection is machine-checkable (Section 28). `tools/validate.py` implements INV-005 (missing targets) and INV-006 (cycles) but no check for invalid combinations.

## Recommendation

Add a machine-checkable invariant (or extend INV-005/INV-006) that detects contradictory relationship combinations on the same task.

## Decision

Status: accepted

Rationale:
A typed relationship representation (`**Relationships:**`) will be added to SPEC.md, the validator, the schema, tests, and conformance fixtures so invalid relationship combinations are machine-checkable.

## Verification

Status: verified

Evidence:
- `SPEC.md` §23.3 defines the typed `**Relationships:**` representation; §28 lists INV-013.
- `tools/validate.py` implements INV-013 (a task both `depends-on`/`requires` and `conflicts-with` the same target) and extends INV-005 coverage to relationship targets.
- `schemas/plan.schema.json` adds task `relationships` items in `<type> P###-T###` form.
- `tests/test_invariants.py` adds three INV-013 cases; `tests/test_fixtures.py` maps `invalid-combination` → INV-013.
- `conformance/invalid/invalid-combination/.plan/plans/P001.md` demonstrates the INV-013 violation (`P001-T002` requires + conflicts-with `P001-T001`).

Checks performed:
- `python3 tools/validate.py --root .` → OK, no invariant violations.
- `python3 tools/validate.py --root conformance/invalid/invalid-combination` → reports `INV-013` for `P001-T002` (exit 1).
- `python3 -m unittest discover -s tests` → 25 passed, 0 failed.
