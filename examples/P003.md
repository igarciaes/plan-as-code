# P003 — Extensible Provider Support

**Status:** Active
**Scope:** `src/auth/`
**Planner:** planner-agent
**Created:** 2026-09-13
**PaC version:** v0.1.0
**Current iteration:** 3

## Objective

Design the authentication layer so additional identity providers can be added over time without redesign.

## Scope

Describe included and excluded artifacts.

### Included

- `src/auth/` extension point.

### Excluded

- Any second provider implementation.

## Constraints

- Only one provider MUST be implemented initially.
- The extension point SHOULD allow future providers without breaking changes.

## Tasks

### P003-T001 — Define the provider extension point

**Status:** Planned
**Owner:** Implementer

Define a minimal extension point that the first provider uses and later providers can reuse.

**Depends on:**

- None

#### Acceptance

- [ ] AC-P003-T001-01 — An extension point exists.
- [ ] AC-P003-T001-02 — The first provider is implemented against it.
- [ ] AC-P003-T001-03 — Adding a future provider does not change existing provider code.

## Decisions

### P003-D001 — Single provider initially

**Context:** The Implementer asked in the P003-T001 feedback thread whether multiple providers must be supported initially.
**Decision:** The first implementation MUST support one provider.
**Rationale:** Limits scope while preserving the abstraction for future providers.
**Affected:** P003-T001
**Resulting changes:** Constraint "only one provider MUST be implemented initially" recorded.
